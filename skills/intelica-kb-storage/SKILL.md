# Intelica KB Storage Skill

Receives `files[]` from `intelica-markdown` (`filename`, `account` or
`null`, `content`) and persists them into `ddvloayza/intelica-brain-ia`
as a single PR, via `intelica-brain-mcp` (project's `.mcp.json`). Makes
no content decisions — Git only.

**Write the PR title, body, and commit messages in English** — the
content it receives from `intelica-markdown` is already in English.

## Step 1 — Check MCP availability

`tool_search` to confirm `intelica-brain-mcp` tools are loaded. **If
not**: create the files locally (`create_file` + `present_files`) and
report that automatic upload wasn't possible — don't block.

## Step 2 — Branch name

`docs/brain-{real-date}-{identifier}` — `identifier` is the main topic's
slug (or `multi`+count if several) + 4 random characters, so it's unique
even if run the same day.

## Step 3 — One single hit: `push_knowledge`

Build `files` for the `push_knowledge` tool (creates branch + uploads
files + opens PR in one call, instead of 3+ separate calls): for each
topic file, `path: inbox/{account}/{filename}` (`inbox/no-account/...`
if `account` is `null`/`N/A`), `content`, and a specific `commit_message`.

If there's an `index.md` and all topics share the same `account`:
include it too (`inbox/{shared-account}/{date}-index.md`). If accounts
differ: don't include it as a file, its content goes in the PR body
instead.

Call `push_knowledge(base_branch="main", new_branch_name=<Step 2>, files=<above>, title=<descriptive>, body=<summary + date + file count + categories + changes>, enviado_por="enviado_intelicaBrain")`.
Never ask for email or personal data — the sender is always that fixed
value.

Fallback if `push_knowledge` doesn't exist (outdated server):
`create_branch` → `create_or_update_file` per file → `create_pull_request`.

## Rules

- **Never `merge_pull_request`** (not exposed as a tool, on purpose) —
  merging always stays with human review.
- Doesn't accept credentials pasted in chat for any action.
- Output: PR link (+ brief summary if `intelica-brain` ran in `--full`).
